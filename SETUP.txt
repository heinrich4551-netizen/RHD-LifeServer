RHD-LIFESERVER - PLUG-AND-PLAY SERVER SETUP
================================================

Author / Maintainer: LT. Toad
Project: RHD-LifeServer
Map: Altis
Framework: AsYetUntitled Framework v5.X.X

This file is the single setup checklist for a new RHD-LifeServer deployment.
It lists the items the server owner must supply or configure manually. Everything
else should be taken from this repository and installed as documented below.

================================================
1. REQUIRED SOFTWARE
================================================

Install these before deploying the server:

[ ] Arma 3 Dedicated Server
[ ] Arma 3 Tools / AddonBuilder
[ ] MariaDB or MySQL-compatible database server
[ ] Database interface required by the selected AsYetUntitled Framework build
    (for example the Framework's supported extDB3 setup)
[ ] Git
[ ] SteamCMD or another supported method for downloading the Arma 3 server
[ ] SimplePersist from Steam Workshop, ID 3006691432

Recommended Windows server tools:
[ ] PowerShell 5+ / Windows PowerShell
[ ] 7-Zip or equivalent archive utility

================================================
2. DOWNLOAD RHD-LIFESERVER
================================================

Clone the repository with its upstream Framework submodule:

  git clone --recurse-submodules https://github.com/heinrich4551-netizen/RHD-LifeServer.git

If the repository already exists:

  cd RHD-LifeServer
  git submodule update --init --recursive

Do NOT delete the framework submodule. RHD expects the upstream Framework to be
available separately from the RHD overlay.

================================================
3. INSTALL SIMPLEPERSIST
================================================

Subscribe/install the published SimplePersist Workshop item:

  https://steamcommunity.com/sharedfiles/filedetails/?id=3006691432

The server startup must load SimplePersist before RHD-LifeServer:

  -mod=@SimplePersist;@RHD-LifeServer

If your server uses additional mods, keep the required mods in the same -mod=
list according to your normal server deployment. Do not copy SimplePersist files
into the RHD repository or into the RHD PBO.

SimplePersist is intended to provide its supported player-state persistence.
RHD should not replace, duplicate, or overwrite SimplePersist's loadout, health,
or position persistence.

================================================
4. BUILD THE RHD PBO AND LOCAL MOD PACKAGE
================================================

Install Arma 3 Tools and locate AddonBuilder.exe.

Build only the RHD addon PBO:

  .\deployment\build.ps1 -ArmaToolsPath "C:\Program Files (x86)\Steam\steamapps\common\Arma 3 Tools\AddonBuilder"

Expected output:

  dist\RHD_LifeServer.pbo

For the complete Arma 3 local-mod folder, use the packaging script:

  .\deployment\package-mod.ps1 -ArmaToolsPath "C:\Program Files (x86)\Steam\steamapps\common\Arma 3 Tools\AddonBuilder"

The package script creates:

  dist\@RHD-LifeServer\
  |-- addons\
  |   `-- RHD_LifeServer.pbo
  |-- keys\
  |   `-- README.txt
  |-- README.md
  |-- SETUP.txt
  |-- LICENSE-RHD.md
  |-- THIRD_PARTY_CREDITS.md
  |-- PBO-Info.txt
  `-- mod.cpp

and also creates:

  dist\@RHD-LifeServer.zip

The resulting @RHD-LifeServer directory is the normal Arma 3 local-mod layout.
Place that folder beside the Arma 3 executable/server root.

The keys directory is intentionally not populated with a fabricated key. If the
server uses signature enforcement, generate the server's real RHD key pair with
Arma 3 DSCreateKey and place the generated public .bikey in the server's normal
keys directory. Keep the private .biprivatekey secure and never commit it.

The Framework mission itself remains a mission/deployment dependency; the RHD
addon is an independent overlay.

================================================
5. SERVER DIRECTORY LAYOUT
================================================

A typical deployment should contain approximately:

  Arma 3 Server/
  |-- arma3server_x64.exe
  |-- @SimplePersist/
  |-- @RHD-LifeServer/
  |   |-- addons/
  |   |   `-- RHD_LifeServer.pbo
  |   |-- keys/ (optional local package metadata)
  |   |-- mod.cpp
  |   `-- README/SETUP documentation
  |-- cfg/
  |-- profiles/
  |-- mpmissions/
  |   `-- Altis_Life.Altis/
  `-- keys/

The exact directory layout can differ with your host panel/provider.

================================================
6. SERVER CONFIGURATION - REQUIRED VALUES
================================================

Start from:

  config/server.cfg
  config/basic.cfg

The repository server.cfg contains safe placeholders. YOU MUST replace:

  CHANGE_ME_ADMIN_PASSWORD
  CHANGE_ME_COMMAND_PASSWORD

with your own strong server passwords.

Never commit real passwords, RCON credentials, database credentials, Steam API
keys, Discord tokens, or other secrets to GitHub.

Recommended production checks:

[ ] hostname is correct
[ ] admin/command passwords are changed
[ ] maxPlayers is appropriate for the hardware
[ ] verifySignatures remains enabled as appropriate for your mod policy
[ ] allowedFilePatching is disabled for production
[ ] BattlEye is enabled
[ ] persistent = 1
[ ] mission rotation/template points to the intended Altis Life mission

The repository default mission template is:

  Altis_Life.Altis

If your actual mission folder has another name, change the server template to
match it.

================================================
7. DATABASE - REQUIRED MANUAL SETUP
================================================

RHD requires a working database setup for the selected Framework deployment.
Database passwords and connection strings are intentionally NOT stored in this
repository.

YOU MUST:

[ ] Create a MariaDB/MySQL database for the server
[ ] Create a database user
[ ] Assign that user the required permissions
[ ] Configure the upstream Framework's database adapter/extDB3 connection
[ ] Import the upstream Framework SQL/schema required by your selected build
[ ] Import database/rhd_extensions.sql
[ ] Verify the RHD state/economy/RP tables exist
[ ] Test a player connection and save/load cycle

RHD's database extensions cover RHD state such as economy telemetry and RP data.
SimplePersist is separate and is not an SQL replacement for the Framework.

Do not paste production database credentials into GitHub files.

================================================
8. MISSION CONFIGURATION - REQUIRED MANUAL SETUP
================================================

RHD's additional virtual items and processing recipes are mission-side because
the upstream Framework reads these definitions from missionConfigFile.

Review:

  custom/RHD_vItems.hpp
  custom/RHD_ProcessAction.hpp

Include those fragments in the actual Altis Life mission configuration where the
Framework's VirtualItems and ProcessAction classes are defined.

Confirm that the resulting mission contains the RHD item keys and recipes.

Resource item keys used by RHD include:

  apple
  peach
  grape
  corn
  cannabis
  coca_leaf
  iron_unrefined
  copper_unrefined
  gold_ore
  diamond_uncut
  oil_sand

RHD processing also uses the appropriate refined/output item keys defined by the
mission configuration.

Do not modify the upstream Framework submodule merely to add RHD content. Keep
RHD mission additions in the mission/custom configuration layer.

================================================
9. 3DEN MAP CONFIGURATION
================================================

Open the Altis mission in Eden/3DEN with the RHD addon loaded.

Place exactly ONE:

  RHD LifeCore Configuration

Then configure:

  Farming Minimum Harvest
  Farming Maximum Harvest
  Mining Minimum Harvest
  Mining Maximum Harvest
  Civilians at 1 Player
  Minimum Civilians
  Maximum Civilians
  Scale Civilians With Players
  Harvest Cooldown
  Dynamic Pricing

Default civilian population target:

  1 player = 115 civilians
  minimum = 60 civilians
  maximum = 115 civilians

Place RHD Resource Node modules at desired farming/mining locations.
Select the resource, yield range, radius, legal/illegal state, and enabled state.

Place RHD Processing Station modules at processing locations. Enter the exact
ProcessAction class used by the mission recipe, for example:

  iron
  copper
  diamond

and the RHD custom processing classes where applicable.

Save the mission after placing/configuring the modules.

================================================
10. F6 / F7 / F8 CONTROLS
================================================

RHD provides:

  F6 = harvesting / processing interaction menu
  F7 = jobs / farming / mining / contracts
  F8 = civilian RP/service actions

Make sure no other client mod or mission key handler conflicts with F6/F7/F8.

The normal Framework shop dialog remains in use while RHD supplies the dynamic
price integration and transaction telemetry.

================================================
12. ANTISTASI ULTIMATE / OTHER MOD INTEGRATIONS
================================================

Antistasi Ultimate is an integration target, not a mandatory base RHD dependency.
Do not mark it required unless a future RHD release actually requires it at
runtime.

When Antistasi Ultimate is installed, RHD's Antistasi compatibility bridge is
limited to the Antistasi-specific integration for the Independent player faction.
All ordinary RHD server/mod functionality remains available to every player.
The Antistasi source itself remains a separate licensed project and is not
modified by the RHD overlay.

Likewise, only add other Workshop dependencies when the code genuinely requires
them.

14. FIRST IN-GAME TEST
================================================

Join as a civilian and test in this order:

1. Confirm RHD initializes without script/config errors.
2. Confirm SimplePersist initializes.
3. Confirm player position/loadout/health persistence behaves according to the
   installed SimplePersist release.
4. Confirm the RHD F6/F7/F8 menus appear.
5. Place/use a farming node and verify harvest output.
6. Place/use a mining node and verify harvest output.
7. Test an illegal resource and confirm illegal job progression.
8. Test a processing station and verify input/output conversion.
9. Open a Framework virtual shop and verify RHD pricing is displayed.
10. Buy and sell a tracked item and verify the economy telemetry changes.
11. Create and complete a delivery contract.
12. Test civilian dispatch/service requests.
13. Test police/EMS authorization with the correct ranks.
14. Restart the server and verify persistence.
15. Check server/RPT logs for script errors.

If Antistasi Ultimate is installed:

16. Confirm the Antistasi mission initializes normally.
17. Confirm Independent players can use the Antistasi-specific RHD bridge.
18. Confirm non-Independent players still retain normal RHD functionality.
19. Confirm Antistasi AI spawning/reveal helpers work without exposing the bridge
    to other factions.

================================================
16. PERFORMANCE / POPULATION NOTES
================================================

RHD dynamically manages civilian population based on active players and configured
limits. The intended default is 115 civilians at one player, with a minimum of 60.

Monitor server FPS, AI count, network traffic, and headless-client requirements
before increasing population limits on a live server.

The optional Headless Client population manager preserves the same population
targeting and moves RHD-managed civilian simulation to a configured HC when enabled.
If no configured HC is available, the server population manager remains the
fallback.

The RHD performance profiler is enabled, but full server-loop logging is disabled
by default to reduce RPT noise. Slow-section logging remains enabled at the
configured threshold. Server owners can enable full loop logging in
config/RHD_LifeServer.hpp when diagnosing performance.

17. AUTOMATED BACKUPS - WINDOWS POWERSHELL
================================================

RHD includes:

  deployment\backup.ps1

The backup script creates a timestamped backup directory containing:

  - a MySQL/MariaDB dump of the configured RHD database
  - the selected server configuration directory
  - database/rhd_extensions.sql
  - a manifest.json describing the backup

The script intentionally does NOT contain database credentials.
Set these environment variables in the account/context that runs the backup:

  RHD_DB_HOST
  RHD_DB_NAME
  RHD_DB_USER
  RHD_DB_PASSWORD

Example manual invocation from the repository root:

  $env:RHD_DB_HOST = "127.0.0.1"
  $env:RHD_DB_NAME = "altislife"
  $env:RHD_DB_USER = "rhd_backup"
  $env:RHD_DB_PASSWORD = "USE-YOUR-REAL-PASSWORD-HERE"
  .\deployment\backup.ps1 -BackupRoot "D:\RHD-Backups" -MySqlDumpPath "C:\Program Files\MariaDB 11.0\bin\mysqldump.exe" -ConfigDirectory "C:\Arma3Server\cfg"

Do not put those values into GitHub files or commit them to source control.
The script passes the password to mysqldump through MYSQL_PWD only for the dump
process and removes that environment variable afterward.

For Windows Task Scheduler, create a scheduled task running as the dedicated
server/backup service account and invoke PowerShell with an appropriate command,
for example:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\RHD-LifeServer\deployment\backup.ps1" -BackupRoot "D:\RHD-Backups" -MySqlDumpPath "C:\Program Files\MariaDB 11.0\bin\mysqldump.exe" -ConfigDirectory "C:\Arma3Server\cfg"

Set the RHD_DB_* environment variables for that service account before enabling
the schedule. Choose a schedule appropriate to your server; a 30-minute backup
cadence is consistent with the repository's default operational backup interval,
but the external scheduler controls when this script actually runs.

The backup script is an operational backup tool; it does not replace testing
restore procedures. Periodically restore a backup to a separate test database and
verify that it is usable.

================================================
19. TROUBLESHOOTING
================================================

RHD PBO does not load:
  - Verify the PBO is in @RHD-LifeServer\addons.
  - Verify @RHD-LifeServer is in -mod=.
  - Verify the PBO was built with Arma 3 AddonBuilder.
  - Check the RPT for config/CfgPatches errors.

SimplePersist missing:
  - Install Workshop ID 3006691432.
  - Verify @SimplePersist is present in the server's loaded mod list.
  - Verify @SimplePersist appears before @RHD-LifeServer.
  - Check the server RPT for SimplePersist initialization errors.

No farming/mining:
  - Confirm the 3DEN resource node exists and is enabled.
  - Confirm the player is within the configured radius.
  - Confirm the mission has the expected RHD virtual item.

Processing fails:
  - Confirm the 3DEN processing station's ProcessAction class exactly matches
the mission recipe class.
  - Confirm the input/output virtual items exist in missionConfigFile.

Database errors:
  - Verify the Framework DB adapter/extDB3 configuration.
  - Verify the database user permissions.
  - Verify database/rhd_extensions.sql was imported.
  - Review the server RPT and database adapter logs.

Antistasi integration errors:
  - Verify the Antistasi Ultimate mission/mod is installed separately.
  - Verify the RHD addon loads after the Antistasi component that supplies the
    functions being bridged.
  - Verify the affected player is Independent for Antistasi-specific bridge calls.
  - Verify ordinary RHD functionality remains available to all players.
  - Review ANTISTASI_INTEGRATION.md and the server RPT.

Backup script errors:
  - Verify PowerShell can run deployment\backup.ps1.
  - Verify mysqldump.exe exists at the path supplied with -MySqlDumpPath.
  - Verify RHD_DB_HOST, RHD_DB_NAME, RHD_DB_USER, and RHD_DB_PASSWORD are defined
    for the account running the task.
  - Verify the backup destination is writable.
  - Review the generated manifest.json and command output.

F6/F7/F8 unavailable:
  - Verify the RHD PBO loaded.
  - Check for key conflicts with other mods/mission scripts.
  - Check the RPT for RHD UI initialization errors.
